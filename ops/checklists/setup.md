# M0 — Setup Checklist

Accounts and services for Family Care. Everything here is **free** (see [build-plan §6](../../docs/build-plan.md), D20). Nothing here involves real health data.

Tick each box as you go. Screens and menu names change over time; if something doesn't match, note it here.

**App identifier** (Android application ID, permanent — D21): `io.github.lgpy.familycare`
Use this exact value wherever a package name / application ID is asked (Firebase Android app, Google OAuth Android client, signing setup).

---

## 1. Password manager (first, because everything else goes in it)
Already have one. Just check:
- [ ] Create a folder/vault **Family Care**. Every password, recovery code and key created below is saved there immediately.
- [ ] The password manager itself has two-factor authentication on, and its recovery codes are stored offline (paper, safe place).
- [ ] It can store **file attachments** (needed for the signing keystore in §8). Some free plans can't (e.g. Bitwarden Free). If yours can't: keep the keystore on an encrypted USB stick plus one encrypted cloud copy, and its passwords in the manager.

## 2. Google accounts (yours and Mom's)
These become the keys to the health data (D12).
- [ ] **Your** Google account: 2-Step Verification on (myaccount.google.com → Security). Prefer passkey or Google prompt over SMS.
- [ ] **Mom's** Google account: 2-Step Verification on. Recovery phone/email up to date.
- [ ] Both: check *Security → Your devices* for unknown devices.

## 3. GitHub
- [x] Account with two-factor authentication on (authenticator app or passkey).
- [x] Create a **private** repository `family-care`. Don't push yet; we connect the local folder in M1.
- [ ] Repository Settings → *Advanced Security* (left sidebar, under "Security"): turn on **Dependabot alerts** (free; warns about vulnerable libraries).
- Note: GitHub's own secret scanning and push protection are **not available for private repositories on the free plan** ([GitHub pricing](https://github.com/pricing)). Instead, M1 adds a free secret scanner (gitleaks) that runs before each commit and in the automated checks, plus ignore rules for keystores and config files.

## 4. Supabase
- [x] Account with MFA on (Account → Security).
- [x] Organization on the **Free** plan.
- [x] Project **family-care-dev** — region: an EU region (e.g. *Frankfurt* `eu-central-1`; *Paris* or *Ireland* also fine — choose the one PowerSync also offers, see §6).
- [x] Project **family-care-prod** — **same region**.
- [x] For each: database password generated by the password manager (long, random), saved.
- [x] **DPA:** nothing to sign — Supabase's Data Processing Addendum automatically forms part of its Terms of Service ([supabase.com/legal/dpa](https://supabase.com/legal/dpa)). Save the page as PDF (with its version date) in a private folder for our records.
- [ ] Optional: subscribe to changes of Supabase's sub-processor list ([link](https://supabase.com/legal/customer-resources/subprocessor-list)).
- [x] Do **not** enter any real patient data in either project.

## 5. Google Cloud / Firebase (one project for sign-in and push)
One project serves both Google sign-in and push notifications.
- [x] console.firebase.google.com → create project **family-care**.
  - [x] When asked: **disable Google Analytics** (D17).
- [x] Do **not** enable Crashlytics, Analytics, Firestore, Hosting or any other Firebase service. Only Cloud Messaging is used (in M4).
- [x] Google Cloud console (same project) → *APIs & Services → OAuth consent screen*:
  - [x] User type **External**, publishing status **Testing**.
  - [x] App name *Family Care*, your email as support contact.
  - [x] Scopes: only `openid`, `email`, `profile`.
  - [x] Test users: your Gmail and Mom's Gmail.
- [ ] OAuth client IDs: **wait until M1** — the Android client ID needs the signing key's fingerprint (§8).

## 6. PowerSync
- [x] Account with MFA if offered.
- [x] Note which **EU region** PowerSync Cloud offers, and make sure the Supabase projects (§4) are in the same or a nearby EU region.
- [ ] Create instances later (M1) — nothing to configure yet.
- [ ] DPA: usually part of the terms you accept at signup; if there's a separate DPA page, save it as PDF.

## 7. Backblaze B2 (independent backups)
- [x] Sign up and choose the **EU Central** region **at signup** (the region is fixed per account).
- [ ] MFA on.
- [x] Create a **private** bucket `family-care-backups` with **Object Lock enabled** (can only be turned on at creation). Default retention: *Compliance* mode, 30 days.
- [x] Create an **application key** limited to that bucket, with *write* and *list* rights only — **no delete**. Save key ID + key. This is what the nightly job will use (D15).
- [ ] DPA: usually part of the terms you accept at signup; if there's a separate DPA page, save it as PDF.

## 8. Development machine (prepares M1)
- [ ] Install **Android Studio** (latest stable). In its SDK Manager, make sure the latest Android SDK Platform and Build-Tools are installed (D22).
- [ ] Create the **release signing key** (Android Studio: *Build → Generate Signed App Bundle/APK → Create new*, or `keytool`). Save:
  - [ ] the keystore file → password manager (as attachment) **and** offline backup (USB stick in a safe place)
  - [ ] keystore password, key alias, key password → password manager
- [ ] Note the key's **SHA-1 fingerprint** (needed for the Google OAuth Android client in M1).
- [ ] Never put the keystore or its passwords in the repository.

## 9. Phones
- [x] Your Honor 200 and Mom's Samsung: Android and security updates installed; screen lock (PIN/fingerprint) on.
- [x] Note Android version of each: Honor 200 `16` · Samsung A26 `17`
